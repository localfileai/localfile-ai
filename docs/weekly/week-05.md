# 5주차 — 원클릭 배포본 (설치 파일 하나로 쓰는 앱)

> 작업 브랜치: `claude/be1-week-3-tasks-peajyw`
> 계기: "누구든 다운받아서 실행하면 자기 로컬 PC에서 쓸 수 있어야 하는데,
> 지금은 명령어를 계속 수기로 입력해야 한다" — 팀 요구로 착수.

## 문제: 4주차까지의 앱은 "개발자만" 실행할 수 있었다

| 조각 | 4주차까지 | 사용자가 겪는 것 |
|---|---|---|
| 프론트(Electron) | `npm run dev` | 터미널 필요 |
| 백엔드 | `npm run backend:dev` | 터미널 하나 더 |
| Ollama·모델 | `ollama pull` ×3 | 명령어 + 6.5GB 판단을 사용자가 |

`electron/main.ts`는 백엔드의 존재 자체를 몰랐고, electron-builder는 설치만
돼 있고 **빌드 설정이 없었다**. 이번 주에 이 셋을 전부 앱 안으로 넣었다.

## 결정 (팀 승인)

| 항목 | 결정 | 이유 |
|---|---|---|
| Ollama | **앱이 자동 설치** | 배포본을 작게 유지하면서 사용자는 버튼만 누른다 |
| 기본 모델 | **경량 기본(약 2.2GB) + 선택 업그레이드** | 필수 2개로 전 기능이 동작. 7.8b는 GPU 사용자만 |
| 배포 형태 | **설치형 Setup.exe (NSIS)** | 시작 메뉴·바탕화면 아이콘·정식 제거 지원 |

경량 기본이 성립하는 근거: **분류·검색은 임베딩 모델이 담당하고 LLM은 파일명
생성에만 쓰인다**(3주차 분류 일원화). 그래서 2.4b만 있어도 기능이 빠지지 않고,
품질 차이는 파일명 추천에만 나타난다(3주차 실측 84% vs 80%).

## 1. 데이터 저장 위치 수정 — 설치형에서 드러난 결함

4주차에 `BASE_DIR`을 **실행 파일 옆**으로 잡았는데, 설치형에서는 이게 깨진다:

- `C:\Program Files\...` 아래는 일반 사용자에게 **쓰기 권한이 없다** → 색인·이력 저장 실패
- (기존 이유였던 _MEIPASS 임시 폴더 문제도 그대로)

수정: 색인·작업 이력을 **사용자 데이터 폴더**(`%LOCALAPPDATA%\LocalFileAI`)에
저장한다. Electron이 자기 `userData` 경로를 `LOCAL_FILE_AI_HOME`으로 넘기면 그걸 쓴다.

덤으로 **한글 계정명 문제**도 막았다: ChromaDB 1.5.x는 경로에 한글이 있으면
절대 경로로 색인을 열지 못하는데(3주차에 발견), 사용자 계정이 한글이면
`C:\Users\강인혁\AppData\...`가 되어 그대로 재현된다. `run.py`가 시작할 때
작업 폴더를 데이터 폴더로 옮겨(`os.chdir`) 상대 경로 우회가 항상 성립하게 했다.

## 2. 첫 실행 준비 API — `GET /setup/status` · `POST /setup/models`

`ollama pull`이 하던 일을 API로 옮겼다 (`app/setup/provision.py`).

- **상태**: Ollama 실행 여부 / 필수·선택 모델 보유 여부 / 색인 상태 / 다운로드 진행률
- **다운로드**: 없는 모델만 골라 백그라운드 스레드로 받는다. Ollama의 스트리밍
  진행률을 **레이어별 합**으로 집계해 전체 퍼센트를 만든다 (레이어가 바뀔 때마다
  진행 바가 되감기는 현상 방지)
- 구조는 색인(`indexer.py`)과 같다: 오래 걸리는 일은 백그라운드 + 상태 폴링

## 3. Electron이 백엔드를 직접 띄운다 — 터미널 소멸

`electron/backend.ts` (신규):

- 앱 시작 시 `server.exe`를 자식 프로세스로 실행하고 `/health`가 응답할 때까지 대기
- **이미 떠 있으면 그걸 쓴다** — 개발 중 uvicorn과 이중 기동으로 포트가 충돌하지 않는다
- 종료 시 **프로세스 트리를 통째로 정리**(`taskkill /T`). PyInstaller onefile은
  부트로더(부모)가 실제 파이썬 프로세스(자식)를 띄우는 구조라, 부모만 죽이면
  자식이 남아 포트를 붙잡는다
- 창을 먼저 띄우고 백엔드를 붙인다 — 사용자는 검은 화면 대신 진행 안내를 본다

`electron/ollama.ts` (신규): 공식 설치본을 내려받아 실행까지 걸어 준다.
실패하면 조용히 죽지 않고 **공식 다운로드 페이지를 브라우저로 열어** 사용자가 막히지 않게 한다.

## 4. 준비 화면 (SetupGate)

`src/components/SetupGate.tsx` — 앱을 감싸는 관문.

- 3단계를 체크리스트로 보여 준다: AI 엔진 시작 → Ollama → AI 모델
- 상황에 맞는 버튼 하나만 노출: **[Ollama 설치하기]** 또는 **[모델 받기 시작]**
- 다운로드 중에는 진행 바 + 현재 모델·단계 표시
- "고품질 모델도 함께 받기" 체크박스 (약 4.8GB, GPU 사용자용)
- 준비가 끝난 사용자는 **이 화면을 보지 않는다**(상태 확인 후 즉시 통과)
- 하단에 "준비 없이 화면만 둘러보기" — 팀원 UI 작업·데모용 우회로.
  이 상태에서는 검색·추천이 동작하지 않는다고 명시

## 5. 설치본 빌드 — `npm run dist:win`

`package.json`에 electron-builder 설정을 넣었다 (이전엔 없었다):

- NSIS 설치본, **사용자 단위 설치(perMachine: false)** — 관리자 권한이 필요 없고
  설치 위치도 쓰기 가능한 곳이 된다
- `server.exe`를 `extraResources`로 동봉 → 앱이 `resources/backend/server.exe`에서 찾는다
- `npm run dist:win` 한 번에: 백엔드 exe 빌드 → 프론트 빌드 → `release/` 에 Setup.exe

## 실기기에서 확인할 것 (Windows)

```powershell
npm run dist:win        # release/ 에 "LocalFile AI Setup x.x.x.exe" 생성
```

그다음 **Ollama와 모델이 없는 상태를 가정하고** 설치본을 실행해:

1. 준비 화면이 뜨는지, [Ollama 설치하기]가 설치 마법사를 띄우는지
2. [모델 받기 시작]의 진행 바가 실제로 올라가는지 (약 2.2GB)
3. 준비 완료 후 폴더 선택 → 검색·추천·적용이 도는지
4. 앱을 끄면 `server.exe`가 작업 관리자에서 사라지는지 (프로세스 잔존 확인)
