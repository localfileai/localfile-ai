# 실험 007: 생성 모델 cold-start 워밍업

작성일: 2026-08-08

## 지난 코드의 한계

기존 백그라운드 웜업은 ChromaDB, 임베딩 모델, 분류 라벨만 준비했다. slim 생성
모델은 첫 사용자 추천 요청에서 처음 적재돼 추가 지연을 만들었다.

## 변경 코드를 통한 보완점

기존 `_warm_up()` 마지막에 `exaone3.5:2.4b` 보유 여부를 확인하고 8토큰 제한의
작은 JSON 요청을 실행한다. 웜업은 기존과 같이 daemon thread에서 실행되며 실패해도
서버 시작을 막지 않는다.

## 실제 결과

```text
전체 웜업:                11.237초
웜업 후 첫 요청 wall:     0.862초
API 내부 elapsed:          0.843초
임베딩:                    0.189초
LLM:                       0.601초
```

웜업 없는 첫 요청 9.448초와 비교해 사용자 첫 요청은 약 90.9% 감소했다. 비용은 앱
시작 뒤 백그라운드 준비 시간으로 이동했다.

## 보완 코드의 한계

저사양 장치에서는 웜업이 CPU·메모리를 사용하며 앱 시작 직후 다른 작업과 경쟁할
수 있다. Ollama가 한 번에 두 모델을 유지하지 못하면 임베딩과 생성 모델이 서로
밀어내 효과가 줄어든다. `LOCAL_FILE_AI_WARMUP=0`으로 비활성화할 수 있다.
