# 결정 기록 (ADR)

되돌리기 어렵거나, 나중에 "왜 이렇게 했지?"가 나올 결정을 남깁니다.

코드는 **무엇을** 했는지 보여주지만 **왜**는 보여주지 않습니다.
3주차에 누군가 이 구조를 뒤집으려 할 때, 이미 검토하고 접은 이유가 여기 있으면
같은 논의를 두 번 하지 않습니다.

## 언제 쓰나

**쓴다**

- 구조를 바꾸는 결정 (저장소 구성, 프로세스 모델, 데이터 흐름)
- 대안이 있었고 하나를 골랐을 때 (모델 선정, 라이브러리 선택)
- 실측 근거로 방향을 정했을 때 (실험 결과 기반 판단)
- 나중에 되돌리기 비싼 것 (데이터 스키마, 파일 포맷)

**안 쓴다**

- 되돌리기 쉬운 것 (변수명, 컴포넌트 분리)
- 사실상 선택지가 없던 것 (React 쓰기로 했으니 JSX 쓴다)

## 형식

`NNNN-짧은-제목.md`, 번호는 순차 증가. 승인된 ADR은 **고치지 않습니다.**
생각이 바뀌면 새 ADR을 쓰고 이전 것의 상태를 `대체됨 → ADR-XXXX`로 바꿉니다.
결정이 바뀐 것도 기록입니다.

```markdown
# ADR-NNNN. 제목 (동사로 끝나면 읽기 좋습니다)

- **상태**: 제안 | 승인 | 폐기 | 대체됨 → ADR-XXXX
- **날짜**: YYYY-MM-DD
- **결정자**:

## 맥락
무엇이 문제였나. 제약 조건은 무엇이었나.

## 검토한 선택지
각 안의 장단점. 접은 이유를 구체적으로.

## 결정
무엇을 골랐고 왜.

## 결과
좋아지는 것, 나빠지는 것, 감수하기로 한 것.
후속 조치가 있으면 체크박스로.
```
