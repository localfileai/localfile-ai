# ADR-0004. 라이선스와 유료화 — 지금 결정해야 하는 것

- **상태**: 제안 (전원 합의 필요)
- **날짜**: 2026-08-05
- **제기**: 강인혁 (BE1)
- **관련**: [ADR-0002 모델 선정](0002-model-selection.md)

창업동아리 사업신고 후 유료 서비스를 검토한다는 이야기가 나왔습니다.
그 전제에서 현재 저장소를 점검한 결과, **지금 상태로는 유료화가 불가능한 항목이
두 가지** 있습니다. 둘 다 시간이 지날수록 되돌리기 비싸집니다.

## 2. 문제 1 — MIT는 유료화와 정반대입니다

MIT는 **"누구나 가져다 고쳐서 팔아도 된다"**는 허락입니다. 의무는 저작권
고지를 남기는 것 하나뿐입니다. 경쟁자가 이 저장소를 통째로 복제해 이름만
바꿔 유료로 팔아도, MIT 하에서는 위법이 아닙니다.

### 이미 공개된 것은 회수할 수 없습니다

라이선스는 앞으로의 커밋에 대해서만 바꿀 수 있습니다. **이미 MIT로 공개된
커밋을 받아 간 사람은 그 시점 코드에 대해 영구적인 MIT 권리를 갖습니다.**
`LICENSE` 파일을 지워도, 저장소를 private으로 돌려도 마찬가지입니다.

### 그래도 지금이 가장 싼 시점입니다

fork 0건 · star 0건 · 공개 10일째입니다. 실질적으로 외부에 유통된 흔적이
없습니다. **지금 바꾸면 비용이 거의 0이고, 6개월 뒤에는 그렇지 않습니다.**

### 선택지

| 안 | 내용 | 유료화 적합성 |
|---|---|---|
| **A. 독점 전환** | `LICENSE`를 "All Rights Reserved"로 교체. 소스는 계속 보이되 사용·복제·배포는 불허 | ★★★ 가장 단순하고 안전 |
| **B. AGPL-3.0 + 이중 라이선스** | 무료 이용자는 AGPL(파생물 소스 공개 의무), 기업 고객은 별도 상용 계약 | ★★☆ 정석이지만 관리 부담 |
| **C. MIT 유지** | 그대로 둠 | ✗ 유료화 시 경쟁자를 막을 수단이 없음 |
| **D. private 전환** | 저장소를 비공개로. 단, 무료 플랜에서는 브랜치 보호가 풀립니다 | 포트폴리오 공개 목적과 충돌 |

**제안: A(독점 전환).** 포트폴리오로 코드를 보여 주는 목적은 public 저장소만으로
달성됩니다. "봐도 되지만 가져다 쓰면 안 된다"가 지금 팀의 의도에 가장 가깝습니다.
B는 유료 고객이 실제로 생긴 뒤에 검토해도 늦지 않습니다.

## 3. 문제 2 — 기본 생성 모델이 비상업 라이선스입니다

**이것이 더 급합니다.** 라이선스를 어떻게 바꾸든 남는 제약입니다.

`exaone3.5:7.8b` / `exaone3.5:2.4b`는 **EXAONE AI Model License Agreement 1.1 - NC**로
배포됩니다. `NC`는 non-commercial이며, 상업적 이용은 LG AI Research와 별도 계약이
필요합니다 (`contact_us@lgresearch.ai`).

즉 **지금 구성 그대로 돈을 받으면 라이선스 위반입니다.**

### 우리 구성의 라이선스 현황

| 구성 요소 | 라이선스 | 상업 이용 |
|---|---|---|
| `qwen3-embedding:0.6b` (검색·분류) | Apache-2.0 | ✅ 자유 |
| `exaone3.5:7.8b` / `2.4b` (파일명 추천) | EXAONE 1.1 **NC** | ❌ **별도 계약 필요** |
| `nomic-embed-text` (예비 임베딩) | Apache-2.0 | ✅ 자유 |
| Ollama | MIT | ✅ |
| Electron · React · FastAPI | MIT | ✅ |
| ChromaDB | Apache-2.0 | ✅ |
| PyInstaller | GPL + 배포 예외 조항 | ✅ (예외 조항이 독점 앱 배포를 허용) |

검색·분류 엔진은 문제가 없습니다. **막히는 것은 파일명 추천 하나입니다.**

### 대안

`Qwen3` 계열 dense 모델(4B·8B 등)은 **Apache-2.0**이고 한국어를 지원합니다.
`qwen3-embedding`을 이미 쓰고 있어 계열도 일치합니다.

다만 ADR-0002에서 exaone3.5를 고른 근거는 **실측한 파일명 품질**(2.4b 84%,
7.8b 80%)이었습니다. **라이선스만 보고 갈아타면 안 됩니다.** ADR-0002와 같은
평가셋으로 다시 재고, 그 결과를 ADR-0002 개정으로 남겨야 합니다.

**당장 해야 할 일은 아니고, 유료화를 결정하는 시점 이전에 끝나 있어야 하는
일입니다.** 무료 배포·포트폴리오 단계에서는 현재 구성이 문제되지 않습니다.

## 4. 문제 3 — 저작권이 5명 공동 소유입니다

한국 저작권법상 여러 명이 함께 만들어 각자의 기여를 분리할 수 없는 저작물은
**공동저작물**이고, 저작재산권 행사에는 **전원 합의**가 필요합니다(제48조).

여기서 나오는 결론:

1. **MIT → 독점 전환도 5명 전원의 동의가 필요합니다.** 한 명이 못 하는 일입니다.
2. **유료 서비스로 파는 것도 마찬가지입니다.** 나중에 한 명이 반대하면 막힙니다.
3. 사업체를 만든다면 **저작재산권을 그 사업체로 양도하는 서면 합의**가
   있어야 깔끔합니다. 구두 합의는 나중에 분쟁의 씨앗이 됩니다.

또 하나 확인이 필요한 것: **이 프로젝트가 수업 과제나 교내 지원 사업의
산출물이라면, 학교 산학협력단이 권리를 주장할 여지가 있습니다.**
창업동아리 담당 부서에 먼저 확인하시길 권합니다.

## 5. "저작권 등록"은 GitHub이 아니라 여기서 합니다

라이선스 파일과 저작권 등록은 다른 것입니다.

- **저작권 자체**는 코드를 쓴 순간 자동으로 발생합니다. 등록해야 생기는 게 아닙니다.
- **한국저작권위원회 프로그램 등록**(<https://www.cros.or.kr>)은 창작 사실과
  창작일을 **추정**받게 해 줍니다. 분쟁 시 입증 부담이 크게 줄어듭니다.
  수수료는 수만 원 수준이고, 사업신고 전에 해 두면 좋습니다.
- **상표**는 또 별개입니다. "LocalFile AI"라는 이름을 지키려면 특허청에
  상표 출원을 해야 합니다. 저작권으로는 이름이 보호되지 않습니다.

## 6. "팀원 외에는 수정할 수 없게" — 이미 돼 있습니다

이건 라이선스가 아니라 저장소 권한 문제이고, [SETUP-REPO.md](../../SETUP-REPO.md)
기준으로 이미 적용돼 있습니다.

- 조직 밖의 사람은 애초에 푸시할 수 없습니다. fork 후 PR만 가능하고, 그 PR을
  병합할지는 팀이 정합니다.
- `main`은 직접 푸시 차단 · PR 리뷰 1건 필수 · CODEOWNERS 리뷰 필수 ·
  force push 금지가 걸려 있습니다.

**다만 구멍이 하나 있습니다: 5명 전원이 `admin`이고 `enforce_admins`가 꺼져
있습니다.** 즉 팀원 누구나 보호 규칙을 우회해 `main`에 직접 푸시할 수 있습니다.
SETUP-REPO.md에도 "쓰지 마세요"라고만 적혀 있습니다. 사업화를 전제한다면
관리자는 1~2명으로 줄이고 나머지는 `write`로 낮추는 편이 안전합니다.

## 7. 제안하는 실행 순서

| 순서 | 할 일 | 담당 | 시점 |
|---|---|---|---|
| 1 | 이 ADR을 팀 전원이 읽고 2번의 선택지(A~D) 결정 | 전원 | 즉시 |
| 2 | 결정이 A라면 `LICENSE` 교체 + README 라이선스 섹션 수정 | BE1 | 합의 직후 |
| 3 | 저작재산권 귀속 서면 합의 (사업체 설립 시 양도 포함) | 전원 | 사업신고 전 |
| 4 | 학교 산학협력단에 권리 귀속 확인 | 팀장 | 사업신고 전 |
| 5 | 관리자 권한 정리 (`admin` 5명 → 1~2명) | BE1 | 즉시 |
| 6 | 한국저작권위원회 프로그램 등록 | 전원 명의 | 사업신고 전 |
| 7 | 생성 모델을 Apache-2.0 계열로 교체 + ADR-0002 재측정 | BE1 · AI | **유료화 결정 전** |
| 8 | 상표 출원 검토 | 팀장 | 서비스명 확정 후 |

**2번은 제가 임의로 하지 않았습니다.** 공동저작물의 라이선스 변경은 전원
합의 사항이고, 한 명이 결정할 수 있는 일이 아니기 때문입니다.
